# 代码审阅

写代码的对话不审自己：敲 `/review`，改动交给一个只读的审阅会话去审，它问原来的对话修哪几条、修完，把报告交回来。

## 它做了什么

- **`/review [目标] [--effort low|medium|high] [--comment]`**：目标不写是未提交的本地改动；数字、`#123` 或 PR 链接是那个 PR（要装好并登录 `gh`）；别的当文件路径。力度不写时本地改动和文件是 medium、PR 是 high。
- **交给审阅会话**：对话填一份交接单（背景、你的决定和原话、实现、改动的文件、不做的、没验证的、重点），调 `review_session`，在同一个项目里另开一个「审阅 · …」会话，这一轮就停下。你在这个对话里说过的话、批准过的计划由插件从记录里原样附上，不经模型转述。
- **审阅会话**：按力度派子智能体（low 不派；medium 三到四个 `review`；high 四个一批，加上 `verify` 跑检查、逐条复核），核实后出报告，每条标 CONFIRMED 或 PLAUSIBLE。原对话在自己的工作树里时，审阅会话也开在那里。
- **只读到原对话答复为止**：审阅会话和它派的子智能体写不了文件，直到它用 `ask_implementer` 问原对话修哪几条、原对话答复了。只问一次：在等答复时、答复以后再问都被拒，免得原对话被一遍遍叫起来答同一件事；之后只修点名的那几条，修完再跑检查。从头到尾不提交。原对话在那一轮里没正面回答时，Plume 拿它那一轮最后说的话当答复交回去；原对话删掉了、没读到就被你停下了，审阅会话什么都不修，发现列在「Awaiting a decision」下面。
- **报告交回**：审阅会话做完、真闲下来后（问原对话的有了答复、修完了；它开着的监视、开发服务器不等），最后那段报告交回原对话（对话里一行「来自新会话」），原对话用几行告诉你发现了什么、修了什么、留下了什么。你按停的审阅不交回。
- **对话里那一行**：「审阅会话 · 审什么」，审阅在跑时扫光，没跑完时说一声，点了打开审阅会话。

## 配合别的插件

- **子智能体**（`plume.subagents`）：medium、high 要派 `review`、`verify` 子智能体；没装时各力度都按 low 自己审一遍，报告里会说明。
- **计划模式**（`plume.plan`）：原对话批准过的计划原文附进交接单。

子智能体、侧边聊天里敲 `/review` 不另开会话，就在那里审完整条流程。

## 用法

装上就能用。改完代码后在对话里敲 `/review`；审 PR 写 `/review 123`，想审得更细加 `--effort high`，要把报告评论到 PR 上加 `--comment`（发之前会问你）。
