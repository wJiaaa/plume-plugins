# 代码审阅

写代码的对话不审自己：敲 `/review`，对话派审阅子智能体去找问题、复核，它们只看得到 diff 和一份审阅背景，看不到写代码时的推理；对话再逐条决定修哪几条、自己修。

## 它做了什么

- **`/review [目标] [--effort low|medium|high] [--comment]`**：目标不写是未提交的本地改动；数字、`#123` 或 PR 链接是那个 PR（要装好并登录 `gh`）；别的当文件路径。力度不写时本地改动和文件是 medium、PR 是 high。
- **审阅背景**：审本地改动和文件时，对话把前因后果填成几项（背景、你的决定和原话、实现、改动的文件、不做的、没验证的、重点），调 `review_brief` 写成临时目录里的 `review/intent.md`，派出去的子智能体都读它。你在这个对话里说过的话、批准过的计划由插件从记录里原样附上，不经模型转述。审 PR 不写。
- **派子智能体**：low 派一个 `review` 看全部；medium 三到四个 `review` 各看一面；high 四个一批，再加 `verify` 跑检查、每条发现派一个 `review` 去驳它。它们画在对话里和「子 Agent」面板里，原始报告在面板里看得到。
- **报告**：每条发现照子智能体写的原样列出，标 CONFIRMED 或 PLAUSIBLE。对话自己不能删掉一条：觉得不对的也照列，在处置里写明是哪行代码说明它不成立；只有 high 里复核的子智能体驳掉的才拿掉，也单列出来。
- **决定修哪几条、修**：每条都有处置——修（范围内的 CONFIRMED）、不修（写明理由：你排除过的、出了范围的、代码说明不成立的）、问你（PLAUSIBLE 或对话里定不下来的，只问这几条）。然后对话修点名的几条、跑覆盖到的检查。从头到尾不提交。
- **在哪里能用**：侧栏里的对话。子智能体里敲 `/review` 不审它自己写的改动，叫你回主对话敲；侧边聊天里敲是审主对话的改动，它就自己按 low 读一遍、只报告不修，报告里写明没有另派审阅者。

## 配合别的插件

- **子智能体**（`plume.subagents`）：各力度都要派 `review`（high 还有 `verify`）。派不了时对话不自己审，提示你去设置 › 智能体打开。
- **计划模式**（`plume.plan`）：对话批准过的计划原文附进审阅背景。

## 用法

装上就能用。改完代码后在对话里敲 `/review`；审 PR 写 `/review 123`，想审得更细加 `--effort high`，要把报告评论到 PR 上加 `--comment`（发之前会问你）。
