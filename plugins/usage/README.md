# 使用统计

在设置 › 数据里、「存储」上面加一页「使用统计」：每一次模型调用按时间、供应商、模型来切，回答「这些请求是什么样的」——今天几点最忙、哪个模型在烧 token、哪个中转慢、首字要等几秒。数据只在本机，不上传。

## 它显示什么

- **工具条**：区间（今天、7 天、30 天、全部、自定义）、供应商筛选、按模型或供应商搜索、自动刷新（5 秒、30 秒、每分钟）、手动刷新、导出 CSV。
- **五格指标**：Token（输入、输出、缓存写入）、请求数和平均每次多少 token、费用、缓存命中率、输出速度和首字时间。
- **柱状图**：今天按小时、其余按天；看 Token、费用、请求数或速度，按模型、模型 · 供应商或供应商拆开堆叠。右边是各系列的数字和占比，点一下从图上拿掉。前八名以外并成「其他」。
- **Token 构成**：这些请求计费的 token 按来源分成十类画成环图（系统提示词、项目说明与记忆、技能与智能体、工具定义、用户消息、注入内容、助手消息、工具结果，输出的思考和回复），下面一行是输入里缓存读取、写入、未缓存各占多少。
- **耗时构成**：等待首字、模型思考、模型回复、工具执行四段的环图，右上角是会话数（含已归档几个）、轮次和工具调用次数。
- **缓存未命中**：本该从缓存读到、却按全价重算的输入有多少，占输入的比例、按当时价格多花多少，按原因分行。
- **热力图**：最近 53 周每天的用量，跟着上面的供应商和搜索筛选，不受区间限制。

## 数字从哪来

Plume 在每次计费的调用时记一笔花销：回复、压缩摘要、插件发起的调用都算，删会话不影响这些数。插件经 `ctx.model.usage()` 读到按小时、供应商、模型合好的数，在界面里筛选和摆放。

- **Token**：输入、输出加缓存写入，不含缓存读取（同一段前缀被一读再读，算进来长会话的总数没法读）。
- **费用**：按调用当时记下的价格算；有请求查不到价时写成「≥」，只是下限。
- **速度**：总输出 token 除以总生成时间，不是各次速度的平均。
- **Token 构成、耗时构成、缓存未命中**：只算会话里一步步发的请求（含子智能体），不含压缩摘要和插件的调用。各部分的比例是发请求那一刻按送进去的内容估的，再把账单上的实数按比例分下去；工具次数和耗时记在调完工具之后的那次请求上。缓存未命中拿同一会话相邻两次请求比：上一次的输入按说都该读到，差的那部分按前缀从哪里变了归因；压缩、撤回之后、换了模型的单独列出。

## 用法

在「扩展」里装上，设置 › 数据里就多出「使用统计」。停用后这一页随即撤下，花销照记。
