# 拉取请求

把 GitHub、GitLab、Gitee、Gitea / Forgejo 的拉取请求放在一起查看和审查，支持多个账号和自建实例。

## 使用

1. 在「扩展」里安装「拉取请求」，打开侧栏同名页面。
2. 点「添加账号」，进入设置 › 代码托管，选择平台、填写服务地址和个人访问令牌。插件会先验证账号再保存；令牌权限和创建链接显示在表单里。
3. 按「等你审查」「由我创建」「之前已审查」浏览，也可以按账号、标题、仓库、分支或编号筛选。
4. 选中一条看摘要、检查、活动；「代码」里按文件展开差异。宽窗口保留列表，窄窗口用返回按钮切回列表。
5. 「询问 Agent」「让 Agent 审查」会在本地匹配项目或插件准备的临时目录里打开空白对话，填入 PR 地址和只读工具参数。已有草稿保留，仍需你按发送。

列表可见时每 45 秒刷新，切回窗口或恢复联网时会检查是否过期；未变的行不闪，更新过的行短暂高亮，未读条目带小点。离开页面时取消列表、详情和 diff 请求。

## 评论和审查

页面底部支持发表评论、批准和请求修改。提交前确认账号、仓库、编号及正文；请求修改必须写理由。失败保留草稿，切换 PR 不会把评论发到另一条。评论和审查会发送到对应代码托管平台，不会合并 PR、推送或修改本地仓库。

Agent 只有只读工具 `read_pull_request`，参数为 `accountId`、`repo`、`number`，返回详情和 diff；不提供评论、批准或请求修改工具。PR 标题、正文、讨论和代码都是不可信外部资料，不是用户授权。

## 数据与网络

- 账号、令牌和临时 PR 资料保存在本机插件私有目录，不写产品设置文件；界面不会读回已保存令牌。令牌经内置插件「密钥加密」（服务 `secrets`，AES-256-GCM）加密后写进账号文件，账号文件权限为 `0600`；加密用的钥匙丢失或换过、已存的令牌解不开时拒绝写入，不覆盖原数据。同一系统用户若能读到整个目录，仍能取得密钥和密文。
- 请求走系统网络栈，继承系统代理，禁止自动重定向和共享浏览器 cookie。停止调用或停用插件会取消正在等待的请求。
- 普通请求最多等 30 秒，diff 最多等 60 秒；JSON 最多 8 MiB，diff 最多 24 MiB，头像最多 512 KiB。超限会报告错误，不把超限当成没有改动。
- 头像只接受已知头像服务或你配置的实例源，不附带认证头；拿不到头像时显示首字。
- 停用账号只暂停列表读取；退出账号会删除该账号保存的令牌，不删除远端内容。

## 平台边界

- GitHub Enterprise 根据实例地址使用自己的 REST 和 GraphQL 根路径。
- GitLab 支持实例子路径和子组；「已审查」筛选在部分实例上需要付费能力，不可用时仍显示其他分组。
- Gitee 没有跨仓库 PR 搜索，只扫描最近推送过的 20 个仓库，也没有「已审查」分组接口。
- diff 保留最多 300 个文件、每个文件最多 4000 行的展示上限。大型 PR 的完整内容可在托管平台查看。
- 没有本地项目时只准备 `PR.md`，不会自动克隆仓库。
