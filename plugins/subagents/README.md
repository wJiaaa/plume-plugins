# 子智能体

输入框输入 `@` 可搜索并点名已启用的智能体，菜单和输入框使用与设置页一致的头像。

让主 Agent 把独立的一件事派到后台：子智能体在自己的上下文中查、改、跑，最后只把结论送回主对话。

## 派发与控制

- `task` 接收 `description`、`prompt` 和可选的 `subagent_type`，立即返回子智能体 ID。主 Agent 可以继续独立工作，结果会自动送回，不需要轮询或重复派发。
- 每个父会话最多同时运行 4 个；额外任务先登记为排队中，能在面板中看到，也能在开跑前停止。
- `task` 的 `resume` 接收原 ID，在同一个子会话里续跑，保留历史、原种类、工具限制和模型。不能把运行中的子智能体重复续跑。
- `stop_subagent` 接收 `id`，只停止这个任务，包括尚未开跑的排队任务。父会话和其他子智能体不受影响。
- 主会话正常结束不影响后台任务。明确停止主会话时，运行中和排队中的子任务全部停止，不再把结果送回。删除会话、停用或卸载插件也会取消对应工作。
- 子智能体不能再派子智能体。风险操作仍经过产品自己的审批卡，卡片会标明来源。

## 交付

- 定义里写了 `output`（一份 JSON Schema：类型、`required`、`properties`、`items`、`enum`）的种类，做完要调用 `yield`，参数就是这份结构。不合格的退回重试，点名缺了或写错的字段；连着三次还不合格，`schemaMode: permissive`（默认）带着警告照收，`strict` 不收。收下以后这一轮就结束；交了个空壳（字段都在、什么都没写）不结束，交回它最后说的话。
- 没写 `output` 的种类做完了照常用正文回答。
- 每跑 60 步（定义里的 `maxTurns` / `max-turns` 可改）是一个检查点，不是上限：清单（装了待办清单插件时的 `todo_write`）比上一个检查点多勾了项就接着跑；一项没勾允许一次，连着两段没勾就停下；一份清单都没写的，有清单工具时先让它把剩下的步骤列出来再跑一段（只给一次）；清单勾完了还在忙的也停下。停下时它会被要求交一份交接（做完了什么、还剩什么、下一步），之后的两步里别的工具都被拒绝，第二步结束这次运行。一次运行最多 200 步，只剩两步时同样讨交接。交回的正文前面写明「到了检查点，还没做完」，上下文留着，可以接着跑。
- 交回主对话的是 `<subagent_result id agent task status>` 包着的正文：交了对象的写成一段字（结论打头、记录压成一行、报告收尾），否则是它最后说的话。停在检查点、原地打转、服务出错时标上 `incomplete`，正文第一句说明原因；还有没回来的子智能体时，提醒主 Agent 先别写最终回答。
- 主 Agent 用 `read agent://<id>` 再读一次交回的结果，`agent://<id>/<字段路径>`（如 `files.0.path`）只取一个字段；没写 `output` 的种类读到的是它的回复。`read agent://` 列出这个对话派出的全部子智能体，id 写后半截也认。只读得到自己这个对话派出的。
- 续跑时上一段交的东西清掉：这一段什么都没交的话，不会把旧的那份当成新结论。

## 界面

输入框上方只显示还在运行或排队的任务。新一批任务派出时会自动打开本会话的「子 Agent」面板；手动关掉以后，普通进度更新不会反复把它打开。工具卡片可以定位到对应的子智能体。

面板顶部可切换任务，显示状态、耗时、工具调用次数、重连和等待批准。派发方交代的任务显示为左侧可折叠任务卡，不冒充用户消息；最终报告单独显示，支持复制，本地转录不会重复显示同一份末条正文。交了对象的回报按结构画：结论在前、是非是一枚章、记录一条一条按严重度排、长文本展开成 Markdown，照收下来的不合格之处列在最后；没跑完的回报标成「未完成的回报」。面板中复用产品的会话视图，所以工具、审批和交付卡沿用同一套实现。

运行中的操控框支持文字和附件插话，不会打断当前工具。任务结束后保留禁用的输入框。未完成的任务有「接着跑」，上下文已删除时可「重新派发」；按钮只在主输入框准备草稿，用户确认发送后才产生新的模型调用。

## 种类与模型

| 种类 | 用途 | 工具范围 | 交回 |
| --- | --- | --- | --- |
| `general` | 通用研究与代码修改，默认种类 | 主会话的工具，不含派发和停止其他子智能体 | 正文 |
| `explore` | 只读搜索与代码定位 | 读、搜索、目录、终端 | `summary`、`files`（`path`、`why`），可选 `architecture`、`report` |
| `review` | 检查代码缺陷与风险 | 读、搜索、目录、终端 | `summary`、`findings`（`file`、`severity`、`problem`、`failure`） |
| `verify` | 执行一项检查并报告结果，不负责修复 | 读、终端 | `passed`、`summary`、`failures`（`name`、`location`、`message`），可选 `command` |
| `plan` | 只读分析与实施规划 | 读、搜索、目录 | `plan`（整份 Markdown） |
| `plan-review` | 只读核实一份实施计划能否照做：事实、范围、步骤、验收 | 读、搜索、目录、终端 | `approved`、`summary`、`blockers`（`problem`、`evidence`、`fix`），可选 `notes` |
| `simple` | 大量机械且边界清楚的改动 | 同 `general` | 正文 |
| `reason` | 先想清楚再动手的难题 | 同 `general` | 正文 |

上面是内置的八种。每种子智能体都可使用自己的 `todo_write` 记事和交差用的 `yield`。

## 设置 › 智能体

顶上一行选看哪一层（个人的，或某个项目的）、条数和搜索；下面「已安装」是这一层自己写的定义，「内置智能体」是上面七种。每一行有脸、名字、工具数、用途，右边是它用的模型、思考档位和开关；悬停时出现复制、删除（改过的内置是「恢复内置」）。点一行打开编辑器：脸（点开挑形状和颜色，骰子换一张没人用的）、名字、范围、用途、指令、允许的工具；没存的改动关掉窗口也留着，按「取消」时先问一句。

- 定义是带 frontmatter 的 Markdown：个人的在 `~/.plume/agents/*.md`，项目的在 `<项目>/.plume/agents/*.md`。同名时项目的盖过个人的，个人的盖过内置的；编辑器只改 `name`、`description`、`tools`、`avatar` 和正文，手写的其他键（`model`、`output`、`schemaMode` / `schema-mode`、`maxTurns` / `max-turns` 等）原样留着，「高级定义」里只读地列出模型和输出结构。改内置的存成个人的一份，内置的模型、脸和输出结构跟着走，删掉它就回到内置。删除是把文件移进废纸篓。
- 模型不选就看定义里的 `model`（这台机器上有那个模型时），再不然跟随主会话；思考档位不选就用默认档。关掉开关的种类不进主 Agent 的子智能体目录，也派不出去。
- 设置和定义只影响新派发：派出去时这一种的指令和工具记在任务上，续跑、重启以后都还是那一份，不换身份或模型。不可用的显式模型会报错，不悄悄退回其他模型。面板输入框下显示实际使用的模型、思考档位和服务商报告的用量。

身份、任务状态、模型偏好、关掉的种类和最终报告保存在插件私有目录的 `subagents.json`，对话保存在产品的会话存储中。重新启动后保留身份与展示；被中断的任务不会自动恢复或花钱，需要由用户确认续跑。插件不读取、保存或向界面传递密钥。
