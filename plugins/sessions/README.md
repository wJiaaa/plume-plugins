# 会话互通

让对话读别的对话、互相递话：在一个对话里定下的事，另一个对话不用你转述；要对方拿主意、帮忙做事，直接问它。

## 它做了什么

- **看得见谁**：侧栏里的对话，和这个对话在同一个项目里、目录相同或一个套着另一个，或者一个是从另一个开出来的（比如计划交给新会话执行）。子 Agent、侧边聊天不算，它们也用不了这几件工具。
- **`list_sessions`**：列出看得见的对话，每行一个地址 `名字 [ref]`（ref 是 id 的前六位，改名以后照样认得），在忙还是闲着，清单上正在做哪一步。
- **`read_session`**：读一个对话此刻的完整记录（请求、回复、工具调用和结果），不打断它、不花它的钱；能翻页、能按关键字找。能读到的不问。
- **`ask_session`**：问一个对话只有它现在答得上来的事（一个判断、一个决定、它会不会碰某个文件），或者请它帮忙做一件事。当场返回，不在原地等：对方闲着就为这封信开一轮，忙着就在两步之间读到；它用 `reply_session` 回，答复作为一条消息送回来、叫起你这边接着做。
- **`reply_session`**：回答问过来的事。对方问过、已经读到、还没答的几封一起答（对方经别的插件寄来的请求也算，比如审阅会话问修哪几条）；要花一阵子的先回一句打算怎么办，做完再回结果（第二句当通知送过去）。
- **`notify_session`**：告诉对方一件改变它下一步的事（交接、挡住了它、放开了一样东西），不要答复。

## 对方没回怎么办

答复总会到，由 Plume 本体兜底（别的插件寄的请求也一样）：

- 对方读到了却没用 `reply_session` 回，那一轮收场时拿它最后说的话代它答（最多 4000 字），标着「没正面回答」。
- 对方的人在它读到之前按了停，代它说「没读到」；对方对话删掉了，代它说「关了」。这两种都没有答复，模型会先回来问你要不要再问。

## 边界

- 别的对话写来的话在对话里画成一行「来自 …」「… 的答复」，点开读全文，旁边的箭头跳到那个对话。它们不是你说的话，不算你对任何操作的授权：对方请这边做的事照这边的权限来，被那边的人拒绝的事不会在这边代办。
- 防止两边原地来回：一封最多两万字（长的写成文件、给路径）；三十秒内一字不差的不重发；同一对之间发得太快的拦下。一条往来链最多经手 28 次、同一个对话最多 10 次，由 Plume 本体数：对方没正面回答、由本体代答叫起的那一轮也接着往下数，你在对话里开口就从头算。
- 你停下一个对话时，攒着还没读的请求丢掉（问的那边会收到「没读到」）；通知和答复留着，不叫醒它，你下次开口时接在你那句后面读到。停下以后再寄来的照常为它开一轮。

## 用法

装上就能用。从别的对话开出来的对话（计划模式的「在新会话里执行」、建议开出的新会话），来源还在侧栏里时系统提示词会告诉它来源在哪：拿不准来源里定下的意图时，先 `read_session` 读，读不出来再 `ask_session` 问它。也可以直接说：

> 问一下「重构登录 [3fa2c1]」那个对话，它会不会改 `auth.ts`，会的话我们先等它。
